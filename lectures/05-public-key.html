    §1 鍵配送問題: なぜ共通鍵だけでは足りないのか

    共通鍵暗号は速くて安全なのに、なぜ別の仕組みが必要なのか。

    共通鍵暗号には、使う前に鍵を安全に共有しておく必要があります。これには2つの壁があります。

    壁 内容 規模の例
    鍵の数 n 人が互いに秘密に通信するには、組ごとに鍵が要る n(n−1)/2 本。1,000 人で約 50 万本
    最初の受け渡し 鍵を送るための安全な経路が、そもそもない 初めて訪れる Web サイトと、事前に会うことはできない

    1976 年に Diffie と Hellman は、発想を逆転させます。鍵を「鍵穴（公開鍵）」と「鍵（秘密鍵）」の2つに分ければよい、というものです。南京錠のたとえが分かりやすいです。

    • 受信者は、開いた南京錠（公開鍵）を誰にでも配る。秘密の鍵（秘密鍵）は自分だけが持つ
    • 送信者は、箱に荷物を入れて南京錠を閉じる。閉じるのに鍵は要らない
    • 箱を開けられるのは、秘密の鍵を持つ受信者だけ

    各人が鍵の組を1つ持てばよいので、鍵の数は n 組で済み、公開鍵は盗聴されてもかまいません。数学で「閉じるのは簡単、開けるのは鍵がないと難しい」を作るのが、第1回 §1 で見た「余りの世界では逆向きの計算が難しい」という非対称性です。

    • 共通鍵暗号には「鍵の数」と「最初の受け渡し」という壁がある
    • 公開鍵暗号は、誰にでも配れる公開鍵と、自分だけが持つ秘密鍵に分けることで、この壁を越える
    • 次の §2 では、その最初の成功例である Diffie-Hellman 鍵交換を見る

    §2 Diffie-Hellman 鍵交換: 公開の値で秘密を作る

    盗聴されている回線で公開の値だけをやり取りして、2人だけが知る同じ秘密に行き着くことはできるか。

    2.1 手順

    公開のパラメータとして、素数 p と、位数が大きな素数 q の部分群の生成元 g を決めておきます（第1回 §5.3〜§5.4）。

    1. アリスは秘密の数 a を選び、A = g^a mod p をボブに送る
    2. ボブは秘密の数 b を選び、B = g^b mod p をアリスに送る
    3. アリスは B^a を、ボブは A^b を計算する。どちらも g^(ab) mod p になる

    下の図で、素数を変えたり秘密を引き直したりして、2人が必ず同じ値に行き着くことを確かめてください。

    2人が同じ値になるのは、(g^b)^a = g^(ab) = (g^a)^b という指数法則だけが理由です。一方、盗聴者イブが見るのは p, g, A, B で、そこから g^(ab) を作るには、A から a を取り出す（離散対数を解く）必要があるように思えます。小さな p なら総当たりで解けますが、q を 256 ビットにすれば手に負えません。

    2.2 弱点: 相手が本物か分からない

    DH は「盗聴」には強いのですが、「なりすまし」には無力です。通信の途中に入り込んで、両方に自分の値を渡す攻撃者を考えます。

    アリスもボブも、受け取った値が本当に相手から来たものかを確かめる手段を持っていません。この中間者攻撃を防ぐには、値に「誰が送ったか」を証明するしるし（署名）を付け、その公開鍵が本人のものだと保証する仕組み（証明書）が要ります。それが第6回のテーマで、TLS 1.3 は DH と署名を組み合わせています（第7回）。

    • DH 鍵交換は、g^a と g^b を交換するだけで、2人が g^(ab) を共有できる
    • 盗聴者が鍵を作るには、離散対数を解く必要がある（ように見える）
    • ただし相手が本物かを確かめられないので、中間者攻撃に弱い。認証は署名と証明書で補う
    • 「ように見える」を、次の §3 で仮定として正確に書く

    §3 困難性の仮定: 何を信じるのか

    「盗聴者には g^(ab) が分からない」を正確に言うと、どんな仮定になるのか。その仮定は、どんな群なら成り立つのか。

    3.1 3つの仮定

    盗聴者に何ができないと仮定するかで、強さの違う3つの仮定があります。下に行くほど、盗聴者にとって簡単な問題が「解けない」と仮定しているので、仮定として強く（より多くを信じて）います。

    仮定 盗聴者に与えるもの 解けないと仮定する問題 言っていること
    離散対数（DLP） g, g^a a を求める 秘密の指数そのものは取り出せない
    計算 DH（CDH） g, g^a, g^b g^(ab) を計算する 共有鍵そのものは計算できない
    決定 DH（DDH） g, g^a, g^b と、g^(ab) か乱数 g^c のどちらか どちらかを見分ける 共有鍵は乱数と見分けがつかない

    DLP が解ければ CDH も解けます（a を求めて B^a を計算すればよい）。CDH が解ければ DDH も解けます（g^(ab) を計算して比べればよい）。だから「DDH が難しい ⇒ CDH が難しい ⇒ DLP が難しい」の順に強い仮定です。

    暗号の安全性の証明では、DDH が要ることが多いです。共有鍵 g^(ab) を、そのまま共通鍵暗号の鍵（第2回の PRG の種のようなもの）として使うには、「乱数と見分けがつかない」ことが必要だからです。

    3.2 群を間違えると DDH が崩れる

    DDH は、群の選び方を間違えると簡単に崩れます。Z_p^* 全体（位数 p − 1 は偶数）で g を生成元にすると、g^x が平方数（ある数の2乗）になるのは x が偶数のときだけです。平方数かどうかはルジャンドル記号で簡単に判定できるので、盗聴者は a と b の偶奇が分かります。

    a の偶奇 b の偶奇 ab の偶奇 g^(ab) は平方数か
    偶 偶 偶 はい
    偶 奇 偶 はい
    奇 偶 偶 はい
    奇 奇 奇 いいえ

    g^a と g^b から「g^(ab) が平方数かどうか」が予測できてしまうので、乱数 g^c と見分けられます。そこで実務では、Z_p^* の中の「位数が大きな素数 q の部分群」だけを使います（p = 2q + 1 の形の安全素数を使い、平方数の部分群に限るなど）。上の図の p がすべて 2q + 1 の形なのはこのためです。

    もう1つの落とし穴は、受け取った値が本当にその部分群に入っているかを確かめないことです。攻撃者がわざと位数の小さな元を送ると、相手の秘密の一部（秘密を小さな数で割った余り）が漏れます（小部分群攻撃）。受け取った公開値の検証は、実装レビューの必須項目です。

    • DH の安全性は、DLP ⇐ CDH ⇐ DDH の順に強い仮定に基づく。証明では DDH がよく使われる
    • Z_p^* 全体では DDH が崩れる。位数が大きな素数 q の部分群を使い、受け取った値がその部分群に入っているかを検証する
    • 次の §4 では、DH の考え方を「公開鍵で直接暗号化する」形に変える

    §4 公開鍵暗号と ElGamal

    「公開鍵で暗号化し、秘密鍵で復号する」方式の安全性は、どう定義するのか。それを DH から作れるか。

    4.1 定義と、決定的ではいけない理由

    公開鍵暗号は、鍵生成 (pk, sk) ← KeyGen、暗号化 c ← Enc(pk, m)、復号 m = Dec(sk, c) の3つでできています。安全性は第2回の IND-CPA と同じゲームで定義しますが、1つ大きな違いがあります。公開鍵は誰でも持っているので、攻撃者は最初から好きな平文を自分で暗号化できるんです。暗号化オラクルが自動的に付いてくる、と言い換えられます。

    その結果、第2回 §4.4 の定理がそのまま当てはまります。

    定理 決定的な公開鍵暗号は IND-CPA 安全ではない。

    攻撃者は、自分で m₀ を暗号化して c* と比べればよいだけです。たとえば平文が「はい」か「いいえ」しかない投票を、決定的な方式で暗号化すると、攻撃者は両方を暗号化して見比べるだけで中身が分かります。公開鍵暗号は、必ず乱数を使う（確率的である）必要があります。

    4.2 ElGamal 暗号

    DH の片方を「毎回使い捨てにする」と、公開鍵暗号になります。

    計算 DH との対応
    鍵生成 秘密鍵 x、公開鍵 h = g^x 受信者の DH の値を、公開鍵として固定しておく
    暗号化 乱数 r を選び、c = (g^r, m · h^r) 送信者が毎回、使い捨ての DH の値 g^r を作る。共有値 h^r = g^(xr) で m を隠す
    復号 m = c₂ · (c₁^x)⁻¹ 受信者は c₁^x = g^(rx) を計算し、それで割る

    毎回違う乱数 r を使うので確率的で、DDH 仮定のもとで IND-CPA 安全です。

    4.3 展性: 暗号文を操作すると、平文も操作できる

    ElGamal には、平文を知らなくても、平文を狙いどおりに変えられるという性質があります。c₂ に s を掛けると、復号結果も s 倍になるんです。

    この性質を展性（malleability）と呼びます。電子投票の集計などでは役に立つ性質ですが（暗号化したまま掛け算できる）、一般の通信では、攻撃者に平文を書き換えられてしまいます。第3回で見た CBC のビット反転と同じ種類の問題で、§6 の IND-CCA で正式に扱います。

    • 公開鍵暗号では暗号化オラクルが自動的に付くので、決定的な方式は必ず不合格。乱数が必須
    • ElGamal は、DH の片方を毎回使い捨てにした公開鍵暗号。DDH 仮定のもとで IND-CPA 安全
    • ただし展性があり、平文を狙いどおりに変えられる
    • 次の §5 では、もう1つの素材である RSA を見る。こちらは素材のままだと、もっと多くの問題を抱えている

    §5 RSA と OAEP: 素材を方式に仕上げる

    第1回で組み立てた RSA は、そのまま暗号化に使ってよいのか。使えないなら、何を足せばよいのか。

    5.1 教科書 RSA の4つの問題

    第1回 §3.4 の c = m^e mod n を、教科書 RSA と呼びます。これは「落とし戸付きの置換」という素材であって、そのまま使える暗号方式ではありません。

    問題 何が起きるか 原因
    決定的 同じ平文は同じ暗号文になる。「はい／いいえ」は見比べるだけで分かる 乱数を使っていない（§4.1）
    展性 暗号文に s^e を掛けると、平文が s 倍になる (m·s)^e = m^e · s^e という掛け算の性質
    小さな平文 e = 3 で m^3 < n なら、暗号文の普通の3乗根を取るだけで m が出る mod n の「巻きつき」が起きていない
    同じ平文を複数人へ e = 3 で同じ m を3人に送ると、中国剰余定理で m^3 が復元できる（Håstad の攻撃） 第1回 §4 の CRT

    展性の怖さは、「この暗号文だけは復号しない」という慎重なサーバでも騙せることです。盗聴した暗号文 c を、別の暗号文に変装させて復号させます。

    5.2 PKCS#1 v1.5 と Bleichenbacher 攻撃

    この問題を避けるために、平文の前に決まった形の詰め物（パディング）と乱数を付けてから RSA に通す方式が、1990年代に広く使われました（PKCS#1 v1.5: 0x00 0x02 乱数 0x00 平文）。

    ところが 1998 年に Bleichenbacher は、サーバが「復号結果が 0x00 0x02 で始まるか」を教えてしまうと、第4回のパディングオラクルと同じ発想で平文を復元できることを示しました。展性を使って暗号文を少しずつ変え、「形が正しい」と言われるかどうかの1ビットを何十万回も集めます。この攻撃は、2017 年にも多くの TLS サーバで再発見されています（ROBOT 攻撃）。

    5.3 OAEP: 乱数とハッシュでかき混ぜる

    現在の標準は OAEP です（Bellare-Rogaway、PKCS#1 v2）。

    教科書 RSA の問題 OAEP での解決
    決定的 乱数 r を混ぜるので、同じ平文でも毎回違う暗号文になる
    展性 暗号文を変えると、復号した X ‖ Y の形（ゼロの並びやハッシュ）が崩れて拒否される
    小さな平文 パディングで n とほぼ同じ長さになり、巻きつきが必ず起きる

    RSA-OAEP は、RSA 仮定（e 乗根を求めるのが難しい）とランダムオラクルモデル（ハッシュを理想的な乱数関数とみなす。第6回）のもとで IND-CCA2 安全であることが証明されています。ただし実装では、復号の失敗の理由をエラーや時間で漏らさないことが前提です。

    • 教科書 RSA は素材。決定的、展性、小さな平文、同報の4つの問題がある
    • PKCS#1 v1.5 のパディングは、形の検査結果が漏れると Bleichenbacher 攻撃で破られる
    • OAEP は乱数と2段のハッシュでかき混ぜ、IND-CCA2 安全になる
    • 次の §6 で、「復号オラクルに耐える」安全性を正式に定義し、実務の標準形であるハイブリッド暗号に進む

    §6 IND-CCA とハイブリッド暗号

    「復号の反応を観察できる攻撃者」に耐えることを、どう定義するのか。現実のシステムは公開鍵暗号をどんな形で使っているのか。

    6.1 IND-CCA2

    §4 の展性も、§5 の Bleichenbacher 攻撃も、攻撃者が「暗号文を復号した結果（の一部）」を知れることが原因でした。そこで攻撃者に復号オラクルを与えたゲームで、安全性を定義します。

    定義（IND-CCA2 安全） 公開鍵と、チャレンジ c* 以外の暗号文を何でも復号してもらえる復号オラクルを持つ、どんな PPT の攻撃者 A についても、|Pr[b′ = b] − 1/2| が無視できるとき、方式は IND-CCA2 安全であるという。

    展性のある方式は、必ず IND-CCA2 を満たせません。c を少し変えた暗号文（c とは別物なので復号してもらえる）を復号させ、その結果から元に戻せばよいからです。上の RSA の図がちょうどその攻撃です。逆に言えば、IND-CCA2 安全な方式は「暗号文をいじっても意味のある平文にならない」ことを保証しています。

    方式 IND-CPA IND-CCA2 仮定
    教科書 RSA × × —
    RSA PKCS#1 v1.5 証明なし ×（Bleichenbacher） —
    RSA-OAEP ○ ○ RSA 仮定 + ランダムオラクル
    ElGamal ○ ×（展性） DDH
    Cramer-Shoup ○ ○ DDH（ランダムオラクルなし）
    KEM + AEAD（6.2） ○ ○ KEM と AEAD がそれぞれ安全

    6.2 ハイブリッド暗号: 公開鍵では鍵だけを運ぶ

    実務では、公開鍵暗号でデータそのものを暗号化することはほとんどありません。公開鍵で運ぶのはランダムな共通鍵だけで、データは第4回の AEAD で暗号化します。この形を KEM/DEM と呼びます。

    理由 内容
    速さ 公開鍵の計算は、AES-GCM より何桁も遅い
    大きさ RSA-2048 で一度に運べるのは 200 バイト程度。長いデータを分割すると、分割の仕方自体が新たな弱点になる
    安全性の組み立てやすさ KEM が IND-CCA で、AEAD が安全なら、全体が IND-CCA になることが証明されている

    KEM（鍵カプセル化）は「ランダムな鍵 K と、それを運ぶカプセルを作る」ことだけに特化した公開鍵の部品です。平文を選ぶ必要がないので、設計も証明もしやすくなります。

    現実の例 KEM の部分 DEM の部分
    TLS 1.3 一時的な (EC)DH（第7回） AES-GCM、ChaCha20-Poly1305
    HPKE（RFC 9180）。MLS や暗号化された ClientHello で使われる DH を KEM として包んだもの AEAD
    耐量子暗号 ML-KEM（第8回） AEAD

    DH は、送信者が毎回 g^r を作って受信者の公開鍵 h と組み合わせれば、そのまま KEM になります（ElGamal から平文を取り除いた形）。TLS 1.3 で RSA による鍵の受け渡しが廃止され、DH だけになったのも、この形のほうが安全性と前方秘匿性（第7回）の点で優れているからです。

    • IND-CCA2 は、チャレンジ以外を何でも復号してもらえる攻撃者に耐えること。展性があると必ず不合格
    • 実務では公開鍵で共通鍵だけを運び（KEM）、データは AEAD で暗号化する（DEM）
    • TLS 1.3、HPKE、耐量子暗号の ML-KEM は、すべてこの形

    §7 鍵長と現状

    RSA や DH の鍵は、何ビットあれば足りるのか。

    第1回 §7.6 で見たように、必要な鍵長は「最良の攻撃の手間」で決まります。RSA と有限体の DH には、数体ふるい法という準指数時間の攻撃があるので、鍵を大きく取る必要があります。楕円曲線には、そういう攻撃が知られていません。

    安全性の水準 共通鍵 RSA・有限体 DH 楕円曲線（ECDH、ECDSA） 目安
    112 ビット 3DES（非推奨） 2048 ビット 224 ビット 現在の最低ライン
    128 ビット AES-128 3072 ビット 256 ビット（P-256、X25519） 長期の保護に推奨
    192 ビット AES-192 7680 ビット 384 ビット
    256 ビット AES-256 15360 ビット 512 ビット

    （NIST SP 800-57 Part 1 の対応表に基づく）

    素因数分解の公開記録は、2020 年の RSA-250（829 ビット）です。RSA-2048 が古典計算機で破られる見通しはありませんが、十分な規模の量子計算機があれば Shor のアルゴリズムで RSA も DH も楕円曲線も破られます。そのため「今は安全でも、通信を保存しておいて将来解読する」攻撃に備え、耐量子暗号への移行が始まっています（第8回）。

    • RSA と有限体の DH は、128 ビット安全に 3072 ビット要る。楕円曲線なら 256 ビットで済む
    • 量子計算機は、この回の方式をすべて破る。移行の話は第8回で扱う

    演習問題

    A. 確認

    1. 100 人が全員と個別に共通鍵で通信するには何本の鍵が要るか。公開鍵暗号なら何組か
    2. p = 23、g = 4、a = 6、b = 15 で DH 鍵交換を手で計算し、共有値を求めよ
    3. DLP、CDH、DDH のうち、どれが一番強い仮定か。理由とともに答えよ
    4. 公開鍵暗号が決定的だと IND-CPA を満たせない理由を、投票の例で説明せよ
    5. KEM/DEM を使う理由を3つ挙げよ

    B. 攻撃と証明

    1. p = 467 の ElGamal で、暗号文 (c₁, c₂) の平文が m であることが分かっている。鍵を知らずに、平文が 2m の暗号文を作れ。また、それを使って IND-CCA2 ゲームに勝つ方法を述べよ
    2. 教科書 RSA で e = 3、n は 2048 ビット、m は 256 ビットの共通鍵をそのまま暗号化した。暗号文から m を求める方法を述べよ
    3. e = 3 の RSA で、同じ平文 m を、異なる公開鍵 n₁, n₂, n₃ の3人に送った。3つの暗号文から m を求める手順を、第1回の CRT を使って説明せよ
    4. DH で、相手から受け取った値 B が、位数 q の部分群に入っているかを確かめる方法を述べよ。確かめないと何が起きるか

    C. 実装

    1. 安全素数 p（512 ビット程度）を生成し、DH 鍵交換を実装せよ。受け取った値の検証も入れること
    2. e = 3 の RSA の同報攻撃（Håstad）を実装せよ（Cryptopals Set 5 の問題 40）
    3. 教科書 RSA の「変装」攻撃（復号オラクルを騙す）を実装せよ（Cryptopals Set 6 の問題 41）

    解答と解説

    A. 確認

    1. 100·99/2 = 4,950 本。公開鍵暗号なら 100 組（各人が1組）
    2. A = 4^6 mod 23 = 4096 mod 23 = 2、B = 4^15 mod 23 = 3。共有値は B^a = 3^6 mod 23 = 729 mod 23 = 16、A^b = 2^15 mod 23 = 32768 mod 23 = 16 で一致
    3. DDH。DLP が解ければ CDH が、CDH が解ければ DDH が解けるので、DDH が難しいことは一番多くを要求している（DDH ⇒ CDH ⇒ DLP）
    4. 公開鍵で「はい」と「いいえ」を自分で暗号化し、投票の暗号文と比べれば、どちらに投票したか分かる。公開鍵暗号では誰でも暗号化できるので、決定的だと必ずこうなる
    5. 速さ（公開鍵の計算は遅い）、大きさ（一度に運べるデータが短い）、安全性の証明の組み立てやすさ（KEM と AEAD がそれぞれ安全なら全体が IND-CCA）

    B. 攻撃と証明

    1. (c₁, 2c₂ mod 467) が 2m の暗号文。IND-CCA2 ゲームでは、チャレンジ c = (c₁, c₂) を受け取ったあと、(c₁, 2c₂ mod p) の復号を依頼する。これは c と別物なので復号してもらえ、2m_b が返る。2⁻¹ を掛けて m_b を求め、m₀ と比べれば b が分かる
    2. m^3 は 768 ビットで n（2048 ビット）より小さく、mod n の巻きつきが起きない。暗号文 c = m^3 は整数としての3乗そのものなので、整数の3乗根を取れば m が出る
    3. c_i = m^3 mod n_i。n₁, n₂, n₃ は（普通は）互いに素なので、CRT で x ≡ c_i (mod n_i) を解くと、x ≡ m^3 (mod n₁n₂n₃)。m < n_i なので m^3 < n₁n₂n₃ となり、x = m^3 そのもの。整数の3乗根を取れば m
    4. 1 < B < p − 1 であることと、B^q ≡ 1 (mod p) であることを確かめる（安全素数なら、平方数かどうかの確認と同じ）。確かめないと、攻撃者が位数の小さな元を送り、共有値の候補が少数に絞られて、こちらの秘密を小さな数で割った余りが漏れる（小部分群攻撃）

    C. 実装のポイント

    • 問題10: 安全素数の生成は、ランダムな q を選んで q と 2q + 1 の両方を Miller-Rabin で判定します。512 ビットでも数秒〜数十秒かかることがあります
    • 問題11: 整数の3乗根は、二分探索か Newton 法で、多倍長整数のまま求めます
    • 問題12: s を乱数で選び、オラクルに c·s^e を渡します。返ってきた値に s⁻¹ を掛ければ m です
